One server missed a deploy. How did that lose over $460 million in 45 minutes?

Design Simplified · 13: the deploy that lost Knight Capital over $460M, and the deploy-safety question interviews ask.

- New code went to 8 servers; 1 server got skipped and nobody checked (no second review).
- The new code reused an old flag. On the skipped server it woke Power Peg (unused order-routing code), dead since 2003.
- Power Peg never knew an order was done, so 212 orders became over 4 million trades: ≈ 19,000 per order.
- The fix made it worse: rolling back the 7 good servers let Power Peg fire on all 8.
- Loss: over $460M in 45 minutes, ≈ $10M a minute.
- Takeaway: check every server's version before go-live, delete dead code, keep a kill switch.

A deploy-safety round in a system design interview often ends here: how do you know every server runs the same version, and how do you stop a runaway system fast?

Simplified from the SEC's 2013 order on Knight Capital.
